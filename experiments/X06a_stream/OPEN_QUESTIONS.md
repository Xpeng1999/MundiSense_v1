# X06a 执行口径

以下执行细节在读取任何本轮模型输出之前登记；不增加方法选择来源。

- 间隔随机种子使用 20261011，各说话人以 seed + speaker_id 派生随机流；句序按 group、dialogue、utt_id 排序。
- MP4 原始时长定义真值区间；WAV 原始时长单独记录。两者原本不完全一致，构造流时不更改真值时长，不把静音填充当成新的真值句。
- VAD 语音阈值的数值集合原文未给出，采用概率阈值 {0.3, 0.5, 0.7}，与最短静音 {0.2, 0.4, 0.8} 做笛卡尔积；两候选共享最短语音 0.3 秒、最长 15 秒。只在 AISHELL-4 train 选择。
- AISHELL-4 RTTM 重叠帧不计入评估，并在重叠区间断开 VAD 状态；无语音帧保留为负类。第 0 通道，不使用说话人识别模型。
- 启动预算使用既有 Q_mix / X02 耗时，保守计入常驻 GPU 进程的等待和 CPU 处理时间；全速阶段先做 CPU 人脸预处理再加载 GPU 模型。S6 先依据启动前估算运行；VAD 实际段数产生后，在 VAD 情绪推理开始前重新核对剩余预算，超过 15 小时即停止。
- v1.1 只替换 JSON 顶层 gate_rules 值的原始字节区间，不重序列化其他字段；H3 默认值和 H_V 的 OP-R80 策略均放在 gate_rules 中，v1 原文件不改。
- S6 使用正确切句、无平滑，先比较与 X05 同口径的逐句决策，再单列新守门规则造成的拒绝。若协议所要求的逐句一致率低于 0.95，立即停止；不会将差异句移出分母。

## 正确切句预处理后的口径核对（只报告，不改规则）

ET-test 1,929 句新鲜人脸处理中，23 句触发固定的第二轨迹分数比例规则。其中 H3/H_ref 各有 21 句在 X05 的 OP-R90 下原本被接受。因此，若 S6 直接与 X05 旧逐句标签（含拒识）比较，即使其余所有预测完全一致，最高也只有 1 − 21/1929 = 0.98911353，无法达到 0.99 验收线。尚未触发 0.95 停止线，继续按原协议执行；新守门输出与去掉守门变化后的诊断一致率分别保留，不替换主口径、不减少分母。该兼容性问题由 reviewer 判断。

## VAD 推理及平滑前登记的组合口径

- Silero 使用原模型 512 样本块，FSMN 使用原在线 frontend 的 1 秒输入块；每个后验只在对应输入和 frontend 前瞻已到达后可用。共享概率阈值状态机、0.3 秒最短语音和 15 秒强制切分；CPU AISHELL 选型与连续流使用相同后验与切分实现，不启用 FSMN 另外一套原生启发式阈值。
- S2 严格先按重叠时长平均各分量，再校准和决策。多个重叠段中只要一个触发固定多脸规则，该真值句即拒识；全部重叠段无脸才走 H_A。同时保留事件级与真值句级触发率。无覆盖句始终计拒识。
- S5 的“先逐 VAD 段校准并平滑”与 S2 的“先平均分量再校准”不具有可交换性。因此 S2 保留原规定口径；S5 单列按时长平均平滑后校准概率的评估，包括 α=0 的同口径对照，不能把两种聚合顺序的差异记作平滑增益。
- 平滑 α 只按默认系统 H3 的 FMH 指标选择（0.005 内选小值），H_ref 复用同一个 α。校准后概率在语音段间延续，包括最终被拒识的段；静默窗口不推进语音 EMA 状态。偏置与阈值保持冻结。
- 离线视频入口仅允许冻结清单中本轮授权的 FMH/ET-test 原始片段；其余视频拒绝启动，避免把通用入口变成本轮未授权数据集的推理入口。

## 实际流正确切句检查补充（在读取该检查的模型输出前登记）

原 `equivalence_attempt2` 重新处理原始单句，使用原始 WAV 和各句从零开始的 X02 5 fps 抽帧；它只能证明单句服务复现，未覆盖 S1 的音频补齐/截断和连续流全局抽帧相位。因此此前 0.98911353 仅保留为单句服务诊断，不能作为完整 S6 结论。补做 `stream_equivalence`：在已经冻结的 S1 音频及全局 5 fps 画面上，给定原句真实起止时间，走与 VAD 段相同的输入适配和冻结推理服务。不得根据 ET-test 输出选择采样相位、音频对齐或模型参数。

新增检查仍使用完整 1,929 句分母和 0.95 停止线；若累计不一致数已使余下句子全部一致也达不到 0.95，提前停止并报告已处理数及全体一致率上界，不把部分结果写成完整测试结果。通过后 FMH 正确切句基线也使用实际流输入，以避免将预处理差异误计为纯 VAD 损失。启动前已将两组共 5,195 句的额外前向及 20% 余量计入预算，更新估计 14.689533 GPU 小时。

实际执行在 1,184 句时触发停止：H_ref 已出现 97 处差异，全体一致率上界 0.949714878。后续 GPU 工作未启动，也未在 ET-test 上选择替代输入处理方式。最终审计与未测项目见 [REPORT.md](REPORT.md)。

- 以 `protocol/X06A_REVISION_1.md` 为修订依据，旧报告逐字节保存在 `REPORT_BEFORE_REVISION_1.md`；旧停止回执、原始单句诊断与 1,184 句实际流输出不覆盖。原 0.95 / 0.99 一致率阈值退出修订后的科学判断。
- S6a 复用既有 1,929 句去除全部守门后的 H3/H_ref 零差异诊断；S6b 在 FMH 按同一组真值句配对 bootstrap 2,000 次、种子 20261011，采用 95% percentile 区间，七类固定 macro-F1。OP-N 差值区间下界 ≥ −0.02 是验收项；点估计 < −0.05 才立即停止。ET-test 不用于判断这一门槛。
- 最短静音选择沿用 S2 原口径：FMH 的 H3，重叠时长加权分量概率后校准、冻结 OP-R90 与多脸守门、拒识计召回分母；0.4 / 0.8 秒相差 0.005 内选 0.4。S6b 则排除多脸规则，单列 OP-N、R90、覆盖率和单分量替换。原 VAD 模型、0.3 阈值及原冻结文件不改。
- 启动预算以最新实际连续流 1,184 句的完整进程墙钟单句耗时更新旧估算，完整保留历史 GPU 账本。CPU 缓存后验仅用于两种配置段数重算，不读取情绪标签。先前原始单句耗时作为历史值，不假定消除 CPU 竞争即可恢复该较快速度。
- 保留既有 `budget_recheck.py` 的串行服务保守上界、未来时间 20% 余量与 300 秒初始化余量。两种 VAD 配置各计一次全速推理；未实现的跨配置缓存共享不计节省。S7 最短静音尚未按 FMH 情绪选择，因此按两候选中较大的回放服务估计预留，而不是假定仍选 0.8。总估计超过修订的 18 小时就停止，不能先花 GPU 再调整估计方法。
