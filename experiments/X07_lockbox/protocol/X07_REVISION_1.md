# X07 修订 1：标签读取隔离

审查日期：2026-10-14
审查对象：PR #9（草稿），分支 `x07-lockbox`，commit `6aa0be9`（L3 GPU 前主动停止）
结论：**授权**按 `experiments/X07_lockbox/STOP_RECOVERY.md` 的范围应用修正，并以替代协议 v2 续跑，另加第 2 节的一项要求。模型、参数包、人脸与 VAD 配置、指标定义、bootstrap、缺失媒体处理和通过门槛全部不变。

## 1. 核对

- **问题：** 原指标脚本计算 SIMS-valid 指标时，先把 `meta.csv` 的整列标签（含 test）读进内存，再筛选 valid。没有人、也没有模型看到 test 标签，实际风险很小；但修正更符合"封存集只在它自己的一次指标计算中被读取"的要求，而且成本低。agent 主动停下，做法正确。
- **补丁：** 先只读 video_id / clip_id / mode 确认 ID 集，再按行号只解析目标划分的标签；并检查"每条记录占一行"，以保证行号对齐。新增两个方向的哨兵测试。实现合理。
- **审查者核对**（不读取标签列）：`meta.csv` 共 4,403 条记录、4,404 个物理行（含表头），满足每条记录一行；划分为 train 2,722 / valid 647 / test 1,034。

## 2. 附加要求：不读标签的检查必须提前

补丁中的 ID 集合检查和"每条记录一行"检查，原本放在领取一次性指标锁**之后**。一旦在 test 上触发，指标锁已经用掉、指标却没有算出，"只计算一次"就无法兑现。因此：

1. 把这两项检查**另做成一个只读身份列的函数**，在 L2 中对 valid 与 test 各执行一次，作为泄漏断言的一部分，写入回执。
2. 指标脚本中，在领取指标锁**之前**再执行一次同样的检查（仍然不读标签）；领取之后只做标签解析。
3. `meta.csv` 的 SHA 已在协议中冻结，两次检查结果必须一致。
4. 补一个测试：两项检查之一失败时，指标锁不被领取。
