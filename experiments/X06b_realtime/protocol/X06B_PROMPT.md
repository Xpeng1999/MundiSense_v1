## 1. 目标与问题

X06a 中，系统在 1 倍实时回放下跟不上输入：墙钟是媒体时长的 1.36 倍，积压最多约 20 分钟；瓶颈是视频解码和人脸检测。本轮回答三个问题：

1. 改造人脸与解码管线后，能否稳定跟上实时？从说完话到出结果要多久？
2. 改造后准确率是否不变差？
3. 用更接近真实的对话时序重测，切句损失是多少？

## 2. 继承与边界

- **冻结、不得改动：** Q_mix（`best_adapter_eval8`）、D1_fmhx、参数包 v1.1、VAD（FSMN，阈值 0.3，最短静音 0.4 秒，`x06_silence_freeze.json`）、平滑 α = 0。默认系统 **只测 H3**；H_ref 本轮不测。
- **调参集与报告集：** 人脸管线的所有选择只在 **FMH**（06/10/11）上做；ET-test 只报告；MER-test、SIMS-valid 不用；CH-SIMS test 零推理；旧目录只读。
- **裁剪操作不变：** 目标人脸始终从**原分辨率帧**上按 X02 的裁剪规则裁出；轨迹排序规则与多脸规则不变。
- 工作区不干净就拒绝启动；每次运行写 run_meta。

## 3. 工作内容

### R1. 管线改造（只允许以下改动）

1. **解码：**
   - 只解出需要的 5 fps 帧（ffmpeg `fps` 滤镜，或等价方式）；
   - 允许使用 GPU 硬解（NVDEC）；
   - 检测用的低分辨率帧与裁剪用的原分辨率帧可以分两路输出。
2. **人脸检测：**
   - YuNet 模型不变，只允许把**检测输入**缩小，候选比例为 1/2、1/3；检测框按比例还原到原分辨率；
   - 允许多进程或多线程并行检测；
   - 只有当 1/3 仍达不到 R2 的吞吐要求时，才允许改用 GPU 检测器。这种情况先停下报告，由 reviewer 批准。
3. **跟踪与裁剪改为增量：** 语音进行中逐帧做轨迹关联和裁剪，语音结束时只做排序和 Q 输入构造。
4. **内存：** 帧只在内存中保留到所属语音段（或静默窗口）处理完；去掉整条流的 JPEG 帧缓存。

### R2. 选定配置（在 FMH 上，预先登记）

- 候选：检测输入 1/2、1/3。按全速模式在 FMH 流上测两项：
  - **生产者吞吐：** 解码加检测的耗时除以媒体时长；
  - **框一致性：** 目标轨迹的检测框与 X02 原管线逐帧的 IoU 中位数，以及 IoU ≥ 0.7 的帧比例。
- 选择规则：在吞吐 ≤ 0.5 的候选中，选框一致性（IoU ≥ 0.7 的比例）更高的那个；两个都不满足吞吐要求时，停下报告。
- 选定后写入 `configs/x06b_face_freeze.json` 并提交，之后不再改动。

### R3. 准确率非劣（门槛）

- 用选定配置，在 **FMH 正确切句流**（X06a 的 FMH 流，不变）上推理 H3；与 X06a 的 FMH 正确切句结果（`fmh_stream_oracle`）逐句配对比较。
- 门槛：OP-N macro-F1 差值（新 − 旧）按句 bootstrap（2,000 次，种子 20261013）的区间下界 ≥ −0.02。
- 同时报告：R90 口径的 F1 差、覆盖率差、Q-AV 与 V2 的 argmax 一致率、无脸句数的变化。
- ET-test 正确切句流同口径只报告。

### R4. 对话时序流与切句重测

- **构造：** 同一说话人的句子仍按 组 → 场次 → 句序号 排列；
  - 同一场次内，两句之间的间隔 = 两句之间所有其他说话人句子的时长之和，加上每次换人时一个停顿，停顿长度在 0.3–1.0 秒之间均匀抽取（种子固定）；
  - 两句之间没有其他人发言时，只加一个停顿；
  - 换场次时，间隔固定为 3 秒；
  - 其他说话人的句子只用来计算时长，不渲染其音视频；间隔内是底噪，画面保持上一帧。
- **底噪水平：** 改为取该句内能量最低的 100 ms 窗口的 RMS，不再用首尾 100 ms（首尾可能含语音）。
- **推理：** 在 FMH 与 ET-test 的对话时序流上做 VAD 切句推理，并与正确切句对照。S2 的映射与计分规则不变；X06a 中"合并 / 切碎 / 一对一"的拆分同样报告。
- **门槛：** FMH 上 H3 的 VAD 切句 − 正确切句 macro-F1 ≥ −0.03（R90 口径，拒识计入分母，与 X06a 相同）。ET-test 只报告；同时报告切句下的中性误报。
- 另外补测最短静音 0.4 秒在 AISHELL-4 test 上的帧级与边界指标（只用 CPU）。
- **局限要写进报告：** 对话时序流假设对方的声音不进入麦克风。

### R5. 实时回放（门槛）

- 用选定配置，在 **X06a 的 4 条 ET-test 流**上做 H3 的 1 倍实时回放。流与 X06a 完全相同，以便前后对比。
- 报告并对比 X06a：
  - 墙钟 / 媒体时长；
  - 输入积压的 P50/P95/最大值，以及随时间的变化曲线；
  - 延迟三种口径：从 VAD 判定结束、从计划 VAD 端点、从真值句结束；
  - 各分项耗时；GPU 显存峰值；进程内存曲线。

## 4. 通过门槛（reviewer 判断，agent 只呈现）

- **R3 非劣：** FMH 上 OP-N F1 差值的区间下界 ≥ −0.02。
- **R4 切句：** FMH 对话时序流上 VAD − 正确切句 ≥ −0.03。
- **R5 实时：**
  - 墙钟 / 媒体时长 ≤ 1.0；
  - 输入积压 P95 ≤ 2 秒，且后半程不高于前半程；
  - 从计划 VAD 端点到输出：P50 ≤ 1.5 秒、P95 ≤ 2.5 秒；
  - 进程内存：从第 10 分钟到结束增长 < 10%。

## 5. 预算

GPU 上限 **14 小时**。预计：R2 全速测量约 1 小时；R3 FMH 加 ET-test 约 2 小时；R4 FMH 加 ET-test 约 3–4 小时；R5 约 3–4 小时（若达到实时，墙钟约等于 3 小时媒体时长）。启动前估算一次，每阶段结束后用实耗重新推算；超过就停在下一阶段开始之前。

## 8. 停止条件汇总

出现以下任一情况，立即停止并报告：
- R2 两个候选都达不到吞吐 ≤ 0.5；
- R3 点估计低于 −0.05；
- GPU 超过 14 小时；
- 泄漏或模态断言失败；
- 根分区可用空间低于 80GB；
- OOM 跳过超过 10 句。

结果不好也照实报告，不得改协议、阈值或标签映射。
